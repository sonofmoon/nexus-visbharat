# Vellore–Tirupati: six-minute jury demonstration

Open http://127.0.0.1:5001/pilot. Say: “This is an isolated synthetic rehearsal, with 63 water-service reports across Vellore and Tirupati. It demonstrates a path from multilingual needs to accountable proposals; it does not claim an existing ministry deployment or measured infrastructure impact.”

| Time | Show | Explain the challenge connection |
|---|---|---|
| 0:00–0:45 | Overview, then Vellore/Tirupati district officer roles | One programme crosses two states and languages. Server-side assignments constrain what each officer can inspect; changing a filter cannot grant access. Six proposed communities need official selection. |
| 0:45–1:45 | Citizen intake: Tamil or Telugu text; optionally record voice | The report receives a durable `NVB-YYYYMMDDXXXX` ticket and private tracking code. Intake survives provider unavailability. The local rehearsal does not call a live model. |
| 1:45–2:30 | Admin → Requests & review → run processing → officer review | Observe the honest manual-review state. Record a faithful English translation, category, urgency and reason. In a configured cloud pilot, regional Google Speech/Vertex perform transcription, translation and classification, with returned usage/model provenance. Urgent operational work is distinct from capital planning. |
| 2:30–3:45 | Proposals & decisions → linked evidence → draft → engineering review → approval | Show the reports behind the candidate and the uncertain source/boundary/cost evidence. Use an explicitly synthetic reference such as `urn:nvb:demo:engineering-review`. An accountable reviewer approves the proposal; this does not transfer treasury funds. |
| 3:45–4:45 | Open Auditor suite; inspect the same proposal, evidence, delivery, outcomes, events, consent and security tabs | Trace a decision to reports and protected audit events. Raise a finding, request evidence and show the independent-closure rule. An unverified document or absent outcome is visible, rather than promoted to proof. |
| 4:45–6:00 | Launch readiness and Programme setup | Show the ten evidence gates, communities, routing, named membership controls, queued work and estimated cost envelope. Present the staged Mumbai/Delhi deployment, four-week controlled opening and six-week evaluation plan. |

Suggested text: Tamil — `எங்கள் தெருவில் குடிநீர் தினமும் ஒரு மணி நேரம் மட்டுமே வருகிறது.` Telugu — `మా వీధిలో తాగునీరు రోజుకు ఒక గంట మాత్రమే వస్తోంది.` Reviewed English — “Our street receives drinking water for only one hour every day.” These are fictional demo inputs.

For deployability, show [the implementation evidence](MINISTRY_PILOT_IMPLEMENTATION_STATUS.md), [the runbook](MINISTRY_PILOT_DEPLOYMENT_RUNBOOK.md) and the validated Terraform package in `deploy/pilot/`. Budget alerts, concurrency caps, outbox recovery and provider-step reuse make cost and failure behaviour inspectable. The proposed ₹1.5 lakh monthly envelope is a planning allowance, subject to regional quotes and actual usage.

For reach and impact, distinguish demonstration scope from future scale: Tamil/Telugu/English and two districts are the tested pilot configuration. New states require configured identities, administrative crosswalks, evaluated languages and measured operating capacity. Ministry value should be measured through routing accuracy, time to prepare a proposal, unresolved backlog and independently verified service follow-up; raw ticket volume is not a beneficiary count.
